## Learned Workspace Facts

- `projectName`, `taskName`, `issueId`, `issueUrl`, `projectPageUrl`, and `taskPageUrl` auto-populate when notion-verification fetches Project/Task rows (**Issue ID** is usually **text**, often `[KEY](https://…)` → **`issueUrl`** parsed from that string). Config also stores **`*PageUrl`** as **`https://`…** links (Ctrl/Cmd+click in the editor) and **`collection://`** data sources for MCP
- **Terminology:** **`Core/memory-bank-paths.mdc`** maps each role to **Notion** first; the **File-based path** column names the same role on disk for a **file-based Memory Bank** (`memory-bank/` + root `tasks.md`) only when that layout applies
- Projects use **Project ID** (numeric); Tasks use **Task ID** (numeric, same convention); `projectId` / `taskId` in config may be JSON **numbers** or **strings** (e.g. `123` or `"123"`)
- If `projectsDataSourceUrl` / `tasksDataSourceUrl` are invalid: find Projects/Tasks databases via Notion search → `notion-fetch` → read `<data-source url="collection://...">` → update config (see `Core/notion-memory-bank-ops.mdc`). **`collection://`** values are required for MCP scoped tools
- Memory Bank subpages in config use **`*PageUrl`** keys (e.g. **`activeContextPageUrl`**, **`creativePageUrl`**); legacy `activeContextPageId`-style keys should be renamed to the matching **`*PageUrl`** names (same string values)
- Notion Memory Bank **Project subpage bodies** (activeContext, progress, etc.): do not repeat the page title as `#` in the body; Notion already shows the title—start sections at `##` (see `Core/memory-bank-paths.mdc` **Subpage body (do not echo page title)**)
- **Active Context** may track **several** parallel tasks via `## Task <taskId> — …` sections; `/van` updates **only** the block for config `taskId`; **`/archive` removes** that task’s section from Active Context (see **`## Active Context: Notion policy and multi-task`** in `Core/memory-bank-paths.mdc`)
- **Notion resolution priority (token-efficient):** **Project** and **Task:** **URL** > **title** — **`Core/notion-verification.mdc`** (Project) and **`Core/notion-task-id-resolution.mdc`** (Task). **`/van`** and **`/change-task`** use those rules. Avoid extra **numeric-ID-only** Notion search or scan steps when a browse **URL** or verified **name** already resolves the row (user: reduce token cost). If browse **URLs** or exact **names** are missing, follow each file’s **incomplete** ask. **`projectId`** / **`taskId`**: duplicate-title tiebreaks and config invariants. Sync page URLs and ids/names from the accepted row when they drift
- **`/van`** requires **task info in the prompt** (description line, task **`https://`…** URL, or explicit **Task ID**); a bare **`/van`** must **stop** with an ask per **`van.md`**. To switch/reload the primary task **without** new description text, use **`/change-task`**; use **`/van …`** when you need full init with an anchored task in the message
- When the primary **`taskId`** changes (`/change-task`, or new/confirmed task during `/van` Step 2), set **`taskPageUrl`**, **`taskName`**, **`creativePageUrl`**, **`reflectionPageUrl`**, and **`archivePageUrl`** to **`null`** in config so **URL**/**title**-tier resolution and task subpages do not target the previous task (stale name would otherwise mis-route title search)
- **`/archive`** updates Notion pages; it does **not** wholesale-reset **`.cursor/notion-memory-bank.json`** or clear **`taskId`**. For the next task, use **`/van`** (including new task) or **`/change-task`** (switch only)
- Command and mode files under **`.cursor/rules/`** (e.g. plan, build, reflect, archive, maps) live in the **repo**—editing them does not pull from Notion or spend Notion tokens. When a step **fetches** a Notion Memory Bank page (e.g. `notion-fetch`), the result is usually the **full** page, so a small in-page edit in Notion can still cost full-page tokens on the next read; refining text **in chat** reuses context until a step explicitly reloads that page
